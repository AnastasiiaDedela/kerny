`src/types/api.d.ts` is generated by `openapi-typescript` from the Kerny API's OpenAPI spec. It is **10,545 lines — about 60% of all TypeScript in this repo**, covering 106 paths and 240 schemas.

## Never read it whole

`Read`ing this file (or a multi-thousand-line slice of it) burns an enormous amount of context to answer what is almost always a ten-line question. It is a lookup table, not a file to understand. Use `Grep`.

Its top-level shape is four exports, so you always know roughly where you are:

| Export       | Line (approx) | Contains                                       |
| ------------ | ------------- | ---------------------------------------------- |
| `paths`      | 6             | One entry per URL, e.g. `"/api/auth/login"`    |
| `components` | 1902          | `schemas`, the named DTOs — `User`, `LoginDto` |
| `operations` | 3946          | Per-operation param/response bundles           |

## Lookup recipes

**Shape of a named schema** (`User`, `ServerDto`, `PaymentMethod`) — this is the common case:

```bash
grep -n "^        User: {" src/types/api.d.ts
```

Schemas are indented 8 spaces inside `components.schemas`. Then `Read` with `offset`/`limit` for just that block.

**Which paths exist for a feature** — cheap, and tells you what endpoints you actually have:

```bash
grep -n '^    "/api/servers' src/types/api.d.ts
```

**Request body / response type for one endpoint**: `grep -n` the path literal to get its line, then `Read` ~40 lines from there. The entry names the `operations` key, which you can grep next if you need the full param list.

## Don't hand-write what you can alias

Reference generated types through `components['schemas']['X']` rather than copying the shape into a local `interface`. The per-domain `types.ts` files exist to do exactly this and give the alias a short name:

```ts
import type { components } from '@/types/api';
export type User = components['schemas']['User'];
```

Import from the domain module (`@/api/auth`), not from `@/types/api`, everywhere except those `types.ts` files — see the `api-layer` skill.

## The one place hand-writing is correct

`SessionResponse` in `src/api/auth/types.ts` is deliberately hand-written, with a comment explaining why: openapi-fetch pipes responses through `Readable<T>`, whose key filter drops properties typed `null`, which strips `user: null` from the unauthenticated branch. If you hit a generated type that doesn't match what a hook actually receives at runtime, this is the reason — narrow it by hand and leave a comment saying so, don't cast.

## Regenerating

`openapi-typescript` is a devDependency but **there is no npm script wired up** for it, and no committed copy of the source spec. Don't guess at a regeneration command — ask which spec URL/file to point it at.
